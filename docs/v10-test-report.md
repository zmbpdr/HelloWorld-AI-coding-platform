## 本轮修复与测试改进

- 修复 `parse_pdf_to_markdown()`：关闭 PyMuPDF 文档后再读取页数会使所有有效 PDF 抛出 `ValueError: document closed`；现在在关闭前保存 `page_count`。
- 后台缺失认证此前由框架默认返回 403；调整为明确的 401，符合接口语义，也使认证测试可断言。
- 上传测试通过临时目录和管理员依赖替身覆盖端点的文件校验逻辑，不再因缺少真实管理员 Token 而跳过。
- RAG 单元测试明确 mock 语义检索，避免测试环境安装 ChromaDB 后意外下载 `all-MiniLM-L6-v2` 模型。

## 尚未满足的产品验收项

1. 学生端 Markdown 的六种语言代码块、表格与任务清单尚未做浏览器人工验收；本轮只确认 TypeScript 编译与生产构建通过。
2. 无向量索引时的关键词降级对中文自然问句很弱。例如课程含“变量用于保存数据”时，查询“变量怎样保存数据”可能没有结果；当前集成用例覆盖稳定的精确关键词链路。应由 RAG 实现补充中文分词/字符 n-gram，或确保向量索引可用。
3. 产品要求的“按教师 `created_by` 隔离 RAG 内容”尚未实现：`Lesson` 模型没有创建者字段，RAG 服务也没有对应过滤条件。因此不能宣称多教师内容隔离已验收；需先补齐数据模型、索引 metadata 和查询过滤后再测。
4. 真实模型回答中的“引用课程内容”仍需在已配置模型与索引的部署环境验收；自动化测试验证的是内容被正确传入 AI 调用。
